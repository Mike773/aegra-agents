# Wiki-контекст на входе json_analyzer_v5

Дата: 2026-08-20. Статус: одобрено.

## Контекст

Аналитик (`json_analyzer_v5`) работает только по числам датасета: вход подграфа —
`raw_json`, `raw_aggregates`, `question`, `direction_key`. Wiki (методика, нормативы,
определения метрик) добывается оркестратором узлом `ground_wiki`, но попадает только
в модель-ответчик (`initial_analysis` / `respond`). Из-за этого аналитик может
неверно истолковать смысл метрики, хотя интерпретация описана в wiki.

Цель: передавать уже добытые wiki-сниппеты в аналитик как справочный контекст —
без новых LLM-вызовов и без wiki-инструментов внутри аналитика.

## Решение

### Контракт входа аналитика

`JsonAnalyzerState` получает опциональное поле `wiki_context: str | None` — готовый
текстовый блок со сниппетами. `None`/пусто → поведение байт-в-байт как сейчас.
Аналитик в easyrag не ходит: добыча wiki остаётся обязанностью оркестратора.

### Оркестратор: формирование и проброс

- Из `_easyrag_system_block` выделяется хелпер `_wiki_snippets_text(state)` — только
  строки сниппетов («[страница / секция]: текст»), без респондерных инструкций про
  заглушки и ошибки. `_easyrag_system_block` использует хелпер.
- `_run_analyzer(..., wiki_context: str | None = None)` кладёт значение во вход
  подграфа.
- Оба вызывателя (`initial_analysis`, `call_json_analyzer`) передают
  `_wiki_snippets_text(state)`. Блок для респондера не меняется.

### Перестановка графа (ходы analytics)

`route → call_json_analyzer → ground_wiki_analytics → respond` меняется на
`route → ground_wiki_analytics → call_json_analyzer → respond` — симметрично
первому ходу, сниппеты всегда свежие под текущий вопрос. Плата — wiki-латентность
перед аналитиком (принято).

### Стадия 1 (сбор)

`compose_system_prompt(overview, wiki_context=None)` добавляет после «Состава
датасета» блок с рамкой: это справка об интерпретации метрик, а НЕ данные — числа
и вердикты только из инструментов, направление метрики только из `metric_type`;
при противоречии верны данные инструментов.

### Стадия 2 (выжимка)

`synthesize` читает `wiki_context` из state и добавляет его в user_content перед
транскриптом с той же рамкой: справка помогает правильно назвать и истолковать
факт, числа — только из данных инструментов; отсутствие wiki в ПРОБЕЛАХ не
упоминается.

### Ошибки

Wiki упала/пусто → `wiki_context=None` → промпты не меняются. Новых фатальных
путей нет.

## Тесты

- `compose_system_prompt` с/без wiki: блок и рамка присутствуют/отсутствуют.
- `_wiki_snippets_text`: сниппеты есть / нет / только заглушки (→ None).
- `_run_analyzer` пробрасывает `wiki_context` во вход подграфа.
- `synthesize` подмешивает wiki в user_content только когда контекст непустой.
- `test_graph_topology_v4` — новый порядок рёбер ходов analytics.

## Вне скоупа

Wiki-инструмент внутри аналитика; отдельные wiki-запросы «под аналитик»;
изменения `_generate_wiki_queries`.
