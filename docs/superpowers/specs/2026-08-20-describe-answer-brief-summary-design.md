# describe_answer: краткое саммари вместо развёрнутого рассказа

Дата: 2026-08-20. Статус: одобрено.

## Контекст

Раздел «Как я пришёл к выводу» (флаг `describe_answer`) дописывался LLM как
развёрнутое описание хода анализа по трассе — до 1200 символов, с целью каждого
вызова и интерпретацией данных. Руководителю нужен короткий итог, а не рассказ.

## Решение

Меняется только текст `DESCRIBE_ANSWER_PROMPT` (prompts.py): LLM пишет краткое
саммари — 2–4 предложения связной прозой, без пошаговой хронологии: какими
данными пользовался (показатели, динамика, сравнение с коллегами, справочная
информация) и как из них следует вывод.

Сохраняется без изменений:

- структура раздела: «Исходные данные» (детерминированная опись) → саммари;
- код `_with_description` / `_describe_trace_llm`;
- фоллбэк при сбое LLM — детерминированный `render_trace` (нумерованный список);
- запреты промпта: внутренние имена инструментов/полей, «критический/проблема»,
  заголовки и рекомендации;
- флаг `describe_answer` (дефолт false) и вырезание раздела из истории.

## Тесты

`test_describe_summary_v4.py`: промпт требует «2–4 предложения», «саммари», «без
пошаговой хронологии», старый лимит 1200 исчез; запреты (situation_overview,
hit_rate, «критический», «рекомендаций») на месте. Существующие тесты
describe_answer зелёные.
